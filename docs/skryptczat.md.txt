**Do wklejenia na Chattr (#kxai):**

@codex spis bugów z dzisiejszego użycia (Telegram bridge vs desktop + reflection/think):

1) **Runtime split / tool availability**  
   Gdy user pisze przez Telegram bridge, agent ma niespójny/okrojony zestaw tooli (np. screenshot = “Nieznane narzędzie”), mimo że ta sama instancja na Windows działa normalnie. Potrzebne: capability negotiation albo jednolity toolset per runtime + twarde błędy.

2) **Checker #kxai co 5 min nie czyta kanału**  
   User mówi, że na #kxai był duży ruch, a checker raportuje “brak nowych”. Podejrzenie: brak realnych `mcp_kxaichattr_chat_read/poll` (błędy połykane), zły channel string, brak cursora/lastSeen, albo duplikaty reminderów psują stan. Job musi logować tool-calle i failować głośno.

3) **Duplikaty reminderów (brak idempotencji)**  
   Łatwo utworzyć 2 identyczne przypomnienia co 5 min. Potrzebny dedupe po (name+message+schedule) + update zamiast create.

4) **“Cron jobs” vs reminders + fixed-time nie odpala**  
   UI/tekst sugeruje cron, ale realnie są reminders (brak cron_*). Interwał 5m działa, ale przypomnienia o stałych godzinach (08:50/12:00/18:30) miały runCount=0 → bug schedulera/cron parsera/timezone.

5) **Reflection/think → brak akcji**  
   Reflection/think wyrzuca trafne insighty, ale “główny agent” nie dostaje tego jako actionable prompt/task, więc nic się nie dzieje. Potrzebna kolejka action items albo reguła: nie wolno pisać “zrobiłem” bez tool-calla w audit logu.

6) **Cortex/Reflection błędnie raportuje stan**  
   Np. “MEMORY.md puste” mimo że nie, “brak MCP” mimo `mcp_status`>0. Potrzebny sanity-check na realnych źródłach.
